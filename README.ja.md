# gphys-physics-2d — Goose で書いた、軽量・高速な 2D 物理エンジン

[English](README.md) | 日本語

円の剛体を、位置ベースの計算(PBD)と一様グリッドで動かします。本体は `gphys.goose` の1ファイル(約430行)です。ヒープ確保も外部ライブラリも使いません。同じ入力なら、いつも同じ結果になります。

- 言語: [Goose](https://github.com/aardappel/goose) v2026.3
- 使い方・事例・性能比較のページ: `docs/showcase.html`(ブラウザで開く)

## できること
- 円の剛体: 重力、はね返り(`restitution`)、摩擦(`friction`)、空気抵抗(`damping`)
- 動かない物体: 質量 0 で作る(釘・壁・床)
- 世界の箱の壁(壁にも、はね返りと摩擦が効く)
- `explode(x, y, 届く半径, 強さ)`: 爆発で吹き飛ばす
- `is_free(x, y, r)`: そこに置けるか(物を出す前の確認)
- `reorder()`: 物体をメモリでも空間の順に並べ直す(`uid` で同じ物体をたどれる)
- `state_hash()`: 決定論の確認(対戦・リプレイの同期チェック用)

## 使い方
```goose
import .gphys;

fn main() {
    gphys::world(0.0, 0.0, 100.0, 100.0, 1.0);   // 箱と、マスの大きさ(いちばん大きい直径以上)
    gphys::gy = -9.8;
    gphys::restitution = 0.2;
    let ball = gphys::add(50.0, 80.0, 0.5, 1.0);  // x, y, 半径, 質量(0 = 動かない)
    gphys::add(50.0, 20.0, 0.5, 0.0);             // 動かない釘
    for f in 60 { gphys::step(1.0 / 60.0, 4); }   // 1/60秒を 4小ステップで
    print(gphys::px[ball], ", ", gphys::py[ball]);
}
```
別のフォルダから使う時は、root のファイルに `import gphys from "<このフォルダへの相対パス>";` と書きます(`examples/` を参照)。

設定はどれも、ふつうの変数です。

| 変数 | 意味 |
|---|---|
| `gx`, `gy` | 重力 |
| `restitution` | はね返り 0〜1。近づく速さが `2 × 9.8 × h` より速い時だけ効く(積み重なりを落ち着かせるため) |
| `friction` | 摩擦 0〜1。ふれている間、小ステップごとに、ずれる速さを この割合だけ減らす(強め。0.05〜0.4 が目安) |
| `damping` | 空気抵抗(1秒あたり) |
| `relax` | 押し戻しの強さ(1 = 重なりを全部なくす) |
| `max_push_speed` | 押し戻しで生まれる速さの上限(深く重なっても、はじけ飛ばない) |

## ファイル
| ファイル | 中身 |
|---|---|
| `gphys.goose` | エンジン本体 |
| `test.goose` | テスト18項目(自由落下・重なり・重心・動かない物体・2000個の積み重なり・決定論・並べ直し・はね返り・摩擦) |
| `bench.goose` | 1000〜10万個のベンチマーク |
| `examples/` | 事例: ゴルトンボード・群衆・砂山・爆発(`pic.goose` は絵を描く部品) |
| `compare/` | 同じアルゴリズムの手書き C・JavaScript 版と、総当たり版。`run.sh` でまとめて測る |
| `docs/` | 使い方・事例・性能比較のページ(`tools/build_showcase.py` で絵を埋め込む) |
| `tools/ppm2png.py` | 事例の PPM を PNG にする(外部ライブラリなし) |

```sh
goose test.goose                               # その場で実行(TinyCC)
goose build bench.goose && ./bench             # C コンパイラで本番ビルド
cd examples && goose build galton.goose && ./galton && python3 ../tools/ppm2png.py galton.ppm
cd compare && goose build cmp.goose && gcc -O2 -o ref ref.c -lm && ./run.sh
```

## 性能(このクラウドのコンテナ・1コア・gcc 13.3 -O2・Node 22・3回の中央値)
1フレーム = 1/60秒を4小ステップ。箱の半分を円で埋めて、重力で落とす場面。

| 玉の数 | Goose | 手書き C | JavaScript | 総当たり(Goose) |
|---:|---:|---:|---:|---:|
| 1,000 | 0.26 ms | 0.25 ms | 0.33 ms | 2.64 ms |
| 5,000 | 1.26 ms | 1.16 ms | 1.76 ms | 66.46 ms |
| 10,000 | 2.16 ms | 2.10 ms | 3.40 ms | — |
| 50,000 | 8.22 ms | 8.57 ms | 11.84 ms | — |
| 100,000 | 17.03 ms | 17.23 ms | 29.30 ms | — |

- Goose と手書き C の衝突数は、全部の規模でぴったり同じでした(同じ計算をしている)
- 同じ機械で他の処理も動いているため、値は回ごとに1〜2割ぶれます。お手元の機械では未確認です

## 速さのしくみ
1. 小ステップごとに、数え上げソート(O(n))で円をマスの順に並べた作業用の配列へ集める
2. 「同じマス+右のマス」と「下の行の3マス」は、どちらもメモリ上で続いた1区間。半分の近傍だけ見る
3. マスの区間を Goose のインデックス型 `u32 upto sx` にして、熱いループの境界チェックをコンパイラに消させる(`goose --bce-lines` で確認)
4. 円 a の値はローカル変数に置いたまま、相手の区間を回す
5. ステップ中に確保も移動も起きない

## 限界(わかっていること)
- 形は円だけ。回転(角速度)・箱・多角形・関節はない
- 深く積むと、少し揺れが残る(2000個の山で、平均の速さ 0.2/秒)。小ステップを増やすと減る
- 1スレッド
- 物体を1つだけ消す関数はない(`reset()` で全部消す)
- 決定論は、同じ機械で確かめた(gcc 版と TinyCC 版でハッシュ一致)。別の CPU どうしでの一致は未確認
